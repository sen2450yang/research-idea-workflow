# 调用示例

这些是可复制的任务提示，不是实际执行结果，也不代表已经完成文献检索或验证。在支持该Skill且已经安装的Codex环境中使用 `$research-idea-workflow`；其他宿主可按其能力读取 `SKILL.md` 并跟随相对路径。

## 从领域开始

```text
使用 $research-idea-workflow。
我的研究方向是【方向】，已有工作和材料见【文件或说明】。
先完成研究背景、领域图谱、跨文献比较和具体研究空白。
不要急着给题目；核心结论要能回到原始研究，保留反对证据和仍未判定的问题。
```

## 大胆构思，但不伪装为已验证

```text
使用 $research-idea-workflow，基于已核实的研究脉络寻找有价值的Idea。
先提出具有解释力的新假说，不要一开始就用审稿式挑刺把想法压掉。
随后分别核查最接近工作、竞争解释和最有信息价值的先导验证。
不限定想法数量，不把技术叠加当创新，也不承诺文献尚未支持的效果。
```

## 只评议已有Idea

```text
使用 $research-idea-workflow，核查以下研究命题的实际创新性：【命题】。
重点比较最相近原始研究和可能推翻前提的证据，明确已知、重复和新增部分。
本轮只交付创新性对照与必要的实质修改，不扩展成完整项目书。
```

## 比较文献冲突

```text
使用 $research-idea-workflow，比较我提供的这些论文。
先对齐对象、变量、时间窗、测量和方法，再判断是真实冲突还是表面冲突。
对无法确定的差异提出竞争解释和区分它们所需的证据，不强行统一结论。
```

## 仅列先导数据，不执行分析

```text
使用 $research-idea-workflow，为这个Idea寻找可能用于先导验证的公开数据。
本轮只核实官方条目、关键字段、对象和访问状态，说明各数据能够及不能回答什么。
不要下载、运行分析或声称已完成先导验证。
```

## 由构想落成方案

```text
使用 $research-idea-workflow，读取当前构想、证据台账和先导记录。
先修正仍影响结论的前提，再形成包含竞争假说、变量、设计、样本/信息量依据、分析、验证、执行与结果判定的完整方案。
没有真实开展的研究基础不要写成已完成；关键缺口不能通过增加技术模块掩盖。
```

## 没有联网权限时

```text
使用 $research-idea-workflow，本轮不要联网，只使用我上传的材料。
可以进行比较、构思和设计，但将依赖外部核查的创新性及最新进展判断明确标为暂定。
```

## 继续已开展的任务

```text
使用 $research-idea-workflow，读取【任务目录】中的实际文件和状态。
根据新增证据更新判断，仅回退受影响阶段，继续完成本轮能够独立成立的工作。
不要把旧结论或“继续”本身当作前提已得到验证。
```
